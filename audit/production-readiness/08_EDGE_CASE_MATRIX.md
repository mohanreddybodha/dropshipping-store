# Production Readiness Audit: Edge Case & Adversarial Scenario Matrix

**Evaluation Criteria**: Behavior under unexpected, adversarial, and asynchronous conditions across Catalog, Pricing, Checkout, Order Processing, and External Supplier Failures  

---

## Adversarial Scenario Matrix

| Scenario ID | Scenario Description | Expected Behavior | Actual Behavior | Severity | Financial / Customer Impact | Recovery Behavior | Test Coverage | Required Action |
| :--- | :--- | :--- | :--- | :---: | :--- | :--- | :---: | :--- |
| **SC-01** | **Customer presses Enter on checkout form** | Form moves focus or prompts for payment method; no order placed without payment. | `handlePlaceOrder` triggers simulated payment, persists unpaid order as `ORDER_PLACED`. | **CRITICAL** | Customer receives free order confirmation; merchant ships unpaid goods. | Manual database cleanup or cancellation. | None | Remove `onSubmit={handlePlaceOrder}` from checkout form. |
| **SC-02** | **Client modifies `amount` to $0.01 in PayPal create request** | Server rejects client price and creates PayPal order for authoritative cart total. | Server accepts `$0.01`, sends it to PayPal; capture accepts verified $0.01. | **CRITICAL** | Direct capital loss; items sold at 99.9% discount. | Manual cancellation or customer dispute. | None | Recompute cart sum from DB variants before calling PayPal API. |
| **SC-03** | **Caller omits `customer_email` in `POST /api/orders/cancel`** | Request rejected with 401/403 Unauthorized. | Email check bypassed; order cancelled and full PayPal refund issued. | **CRITICAL** | Competitor or attacker cancels legitimate customer orders and forces refunds. | Customer complaint; payment processor refund fees. | None | Require authenticated user session or strict email+token match. |
| **SC-04** | **Caller omits `customer_email` in `PATCH /api/orders/address`** | Request rejected with 401/403 Unauthorized. | Email check bypassed; delivery address rewritten to attacker's location. | **CRITICAL** | Physical merchandise hijacked; customer receives nothing. | Customer chargeback; lost inventory. | None | Require authenticated ownership verification. |
| **SC-05** | **Attacker passes `x-admin-email: admin@vastire.com`** | Request rejected with 401 Unauthorized (must verify API key or OAuth JWT). | Header trusted; full admin order listing and status mutation granted. | **CRITICAL** | Complete store takeover; customer PII and financials compromised. | Incident response / breach disclosure. | None | Require `X-Admin-API-Key` with `timingSafeEqual`; remove email header trust. |
| **SC-06** | **Anonymous caller accesses `GET /api/orders`** | Request rejected with 401 Unauthorized. | Fallback query returns last 50 orders with full customer PII and profit data. | **CRITICAL** | Mass customer privacy breach; competitive intelligence leaked. | Public breach disclosure under US privacy laws. | None | Remove parameterless query; require authentication. |
| **SC-07** | **Customer pays $50 on PayPal, capture succeeds** | Server marks order paid AND dispatches order to CJ Dropshipping via `OrderRouter`. | Order saved in DB as `ORDER_PLACED`, but NEVER sent to CJ Dropshipping. | **CRITICAL** | 100% fulfillment stall; parcel never shipped; PayPal account dispute freeze. | Manual order placement on CJ by human operator. | None | Connect PayPal capture flow to `OrderRouter.submit_order()`. |
| **SC-08** | **CJ returns code 1603003 ("Order exist") on retry** | Server queries CJ to verify existing order ID and confirms payload match. | Server marks order `CJ_ORDER_CREATED` with `cj_order_id = None`. | **HIGH** | Tracking and shipment synchronization broken forever for this order. | Manual lookup in CJ portal. | Covered (Asserts success, but ignores missing ID) | Query CJ `/order/list?orderNum=...` to extract actual `orderId`. |
| **SC-09** | **Product runs out of stock in US warehouse** | Storefront displays "Out of Stock" or disables variant purchase. | Storefront continues serving product from static `seedCatalog.json`. | **HIGH** | Customer pays for unavailable item; fulfillment fails. | Manual customer contact and refund. | None | Connect storefront catalog API to live PostgreSQL database. |
| **SC-10** | **4 Uvicorn workers handle traffic simultaneously** | Centralized rate limiter throttles aggregate requests to <= 0.9 QPS. | Each worker has independent bucket; aggregate throughput hits 3.6 QPS. | **HIGH** | CJ Dropshipping returns HTTP 429 or silent empty error 1600200. | Transient failure; order routed to DLQ. | None | Use single Uvicorn worker or inter-process shared rate limiter. |
| **SC-11** | **Admin retries order already in `CJ_ORDER_CREATED` state** | Endpoint rejects retry because order is already in fulfillment. | Router dispatches another order creation request to CJ Dropshipping. | **MEDIUM** | Risk of double fulfillment and paying supplier twice. | Manual cancellation on CJ portal. | None | Assert `order.status == 'MANUAL_REVIEW_DLQ'` before retry. |
| **SC-12** | **Attacker queries `GET /api/user/addresses?email=victim@gmail.com`** | Request rejected with 401 Unauthorized. | Server harvests and returns victim's saved delivery addresses and phone numbers. | **CRITICAL** | Direct PII leak. | Incident investigation. | None | Verify Firebase ID token and match token email against request. |
| **SC-13** | **Customer enters single digit "9" in order lookup ZIP code** | Lookup rejects ZIP code as invalid (must be 5 digits). | Query uses `LIKE '%9%'` and returns orders for anyone with a 9 in their ZIP. | **MEDIUM** | Weakens dual-factor verification; allows order brute-forcing. | None | None | Enforce strict 5-digit ZIP equality (`=`). |
| **SC-14** | **Supplier returns HTTP 200 with `logisticsMiss: true`** | Intercepted as critical error, routed to DLQ, prevented from supplier fulfillment. | Correctly intercepted by Python `OrderRouter` and transitioned to `MANUAL_REVIEW_DLQ`. | **LOW (Mitigated)** | None (Handled safely in Python backend). | Automatic DLQ routing. | Covered (`test_logistics_miss_interception`) | Maintain existing Python assertion logic when unifying backends. |
| **SC-15** | **Third-party website sends cross-origin request with credentials** | Browser blocks request due to CORS Same-Origin Policy. | FastAPI CORS allows `r"^https?://.*"` with `credentials=True`, exposing data. | **HIGH** | Cross-site data leakage from logged-in sessions. | None | Covered (Asserts universal CORS exists, but insecure) | Restrict CORS allowed origins to `https://vastire.com`. |
